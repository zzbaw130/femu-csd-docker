# pg_sina_csd 设备算子

这里的 SO 在容器内编译，由 FEMU CU 执行，逻辑上属于 CSD CPU。Guest PG 扩展在 `code/apps/pg_sina_csd`，负责生成设备参数、直接调用 SNIA 和转换最终结果；设备程序不访问 Guest 文件描述符、不调用 NVMe、不解释 SQL 文本。

## PG 原生计划执行

`plan.c` 编译成 `pg-sina-plan.so`。Guest 以 PG 已选中的连接树为基础，进行分组键过滤下推、计数预聚合等局部改写，转换为 `apps/pg_sina_csd/include/plan.h` 中的节点数组。该格式只属于本应用，FEMU 和 SNIA 没有为 SQL 增加协议。

同一 SO 还提供 `pg_sina_workmem_capacity`：无 AFDM、无标量参数，正常返回共享 `libcs-workmem` 的总容量（字节），由 SNIA 通过 64 位 CompValue 交给 Guest。该调用不创建查询 context，也不分配查询工作内存。CU 数和 FDM 容量仍由 Guest 通过 SNIA 资源查询取得。

入口 `pg_sina_plan` 按顺序接收五个 AFDM：

1. 节点计划与执行器分配的缓冲偏移。
2. 控制记录数组：整树任务及各流水线任务的私有状态句柄、所需页地址、完成/结束/关闭标记。
3. 结果缓冲数组：首项是最终 `qs_result`，其余是设备内部交接批次；内部行紧密存储所需列，不传回 PG。
4. 原始页输入、扫描列批次和字符串字典配置的交接区域。
5. 每个执行槽各 64 KiB 的 spill I/O 缓冲。

本项目约定：`cparam1` 的最低位表示计时开关，其余位为执行槽编号；0 推进整树，1–64 执行当前并行流水线。可用和已消费槽的位图为 64 位，最高槽使用第 63 位；64 槽的完整掩码为 UINT64_MAX。执行槽不是固定的物理 CU 绑定，每次普通 E1 请求占用一个可用 CU。`cparam2` 仍仅由 SNIA 用于 spill 重入。参数顺序由双方代码约定，不改变 SNIA/FEMU 接口，也没有参数解码框架。

并行 Heap 顺序扫描由 Guest 按空闲 worker 提前分配不重叠的数据块，提交 `LOAD→CSF`。CSF 的现有 cparam1 低位保留 profile 和 worker 编号，位 8 表示此次附带已安排的输入，位 9 以上为 Heap 页号；cparam2 仍仅用于 spill 重入。这是本应用的计算参数约定，不改变 SNIA/FEMU 接口。设备接收输入后连续执行当前算子链，CompValue 的低三位分别表示有输出、输入耗尽、worker 完成，省去每块数据的控制记录读取和 ready 写入；有输出尚未被下游消费时不覆盖缓冲。共享 Hash/聚合 Sink 能消费下一批时，在同一次 CSF 内继续处理当前输入块。

其余worker（索引、聚合Source、Combine等）的普通完成同样使用CompValue的有输出/完成位；输入耗尽位仅用于主机分配的扫描块。位3表示仍有页请求需要主机读取控制记录并补交LOAD，已由设备图处理的读取不设置该位。PG可由完成值直接判断是否推进或等待协调端，无须每次读完整AFDM控制记录。新阶段的worker控制记录由设备初始化，PG只清空自己的副本，不读回设备私有state指针。该完成值约定只属于本SQL程序，PG扩展与pg-sina-plan.so须一起构建部署，不改变SNIA/FEMU协议。

通用 SQL 树默认由 `pg_sina_plan` 在查询根 workmem 下创建可换页字典，所有 CU 共享稳定 ID。AFDM 只传初始配置；导入已有 ID 和计划字面量后，正文、ID 目录及哈希桶统一按 64KiB 页面按需 STORE/LOAD，页缓存、描述符和每 CU 访问状态都计入查询预算。独立 CSF 保留原有平铺字典接口。

查询先绑定扫描、Sort 和 Index 实例，再执行算子链。原始 Heap 文本可以直接参与列批次过滤，只将存活输出放入字典；表达式保留 ID 与切片偏移，实际比较才读取字节。每 CU 另保留有限数量的短值副本及其 ID，减少重复分类值对共享字典的访问，该存储也计入 workmem。相等分组和 Hash 等值键直接比较唯一 ID；有序比较及 MIN/MAX 读取真实文本。

内部字典访问返回 NEED_* 时，保留当前输入和游标，用该 CU 最后一个 I/O AFDM 完成后携 token 继续；BUSY 只表示另一个访问尚未完成，不能当成已经产出一批结果。扫描保存页、列和 tuple；表达式与输出物化分别保存进度；排序保留当前比较/堆调整；Join 与聚合在更新成功后才推进。Index 的 namespace 页缓存与字典 spill AFDM 分开，避免重入读取错误缓冲。借用的正文在 unpin 前不会被换出。

查询正常结束时，先关闭算子，再逐一 FREE 字典 token，全部完成才发布结束标志。错误或取消时，PG 先停止相关请求，设备释放查询 workmem，由所属 SNIA 设备会话回收尚未确认的临时 token。默认入口的低内存扫描、排序、最终输出与取消路径已通过原生测试；真实 Guest 的低内存验证与尚存问题见扩展 `doc/performance.md`，不能将组件通过等同于全部 SQL 性能验收。

索引及串行Scan需要namespace页时，设备SQL程序根据PG预先提供的extent映射生成物理读取范围，返回 `csNeedNvmRead`，由FEMU通用设备图完成内部读取并重入同一CSF。映射缺失或一次读取范围超过设备上限时，才把控制记录交回Guest，由其提交 `csQueueStorageRequest(NVM_TO_AFDM)`；独立worker通过SNIA回调续交，协调端由PG线程续交。主机LOAD后的Compute使用已有cparam1中的QP_PAGES_INPUT标志设置就绪状态，省去独立FDM控制写入；该标志不在spill重入时重复应用，与QP_SCAN_INPUT的页号编码互斥，定义见私有plan.h。扫描块由Guest根据FDM容量在4/2/1MiB中选择，索引按需读取8KiB页。原始数据不经过Guest PG缓冲。spill需要时，设备SQL程序返回 `csNeedStore/Load/Free` 完成值，FEMU设备图在隐藏临时空间中执行并重入；SNIA保留非设备图请求的调度路径。PG不接收或解释中间行，FEMU和SNIA不解释表、索引或SQL语义。

Heap 每次 LOAD 的块可包含多个列批次。通用树将列向量限制为至多 2048 行，扫描前用页内 line pointer 数保守选择能放入向量的完整页，再复用原 Scan/Filter ABI。页指针包含无效项时仍保守计数，单页始终容纳得下；实际页与 Tuple 校验继续由 Scan 完成。已加载字节数和解码进度保存在各扫描节点的 workmem 状态中，控制记录可同时供 Index Join 请求缺页；筛选后需要延迟解码的列始终引用当前这批页。该块的所有向量和输出消费完成后才接受下一块，没有新增读取或跨查询缓存。

Guest 从 PG 选定的树中标记可并行的扫描/投影/Hash 或 Index Probe 段，包含初始化和 Hash Build 输入。设备先完成共享 Hash 表，再建立各 CU 独立的游标；Heap 输入由 PG 动态分配，索引及临时分区任务继续从设备原子游标领取。阻塞节点消费投影后的行批次，不重复构建 Hash 表。Guest 通过已有事件和批次请求推进每个完成的槽，FEMU 通用设备图推进内部 I/O 与计算；不需要 SQL 专属固件或代理。

不同流水线依次复用 AFDM；各任务的动态状态通过子 context 计入同一个查询预算。整树节点仍按行拉取组合，中间值保持精确 `qs_cell` 的 int128、精度和 NULL；Scan/Filter 则复用已有列向量和 SIMD 路径。Q1/Q6 继续使用下文的单表快路径。

阻塞Hash Aggregate的输出入口（Source）也可驱动下一条流水线。PG依据HAVING前的分组工作量标记符合条件的聚合后投影/连接路径，设备SQL程序先完成聚合，再让各CU从只读分组表中原子领取64条连续聚合记录的范围；处理完即继续领取，不复制整份聚合结果、不重扫Heap。CU保留自己的输出位置和索引游标，所有读者结束后才释放分组表。聚合若实际spill，或无法分配并行状态，则保留设备内原串行归并/消费路径；不会先消费一行再回退。这里的分组表及游标均属于设备SQL SO，FEMU固件仍只处理通用CSF、CU和I/O。

聚合Source可把最终记录组成至多256行的列批次，覆盖CU领取的驻留分组、串行Hash分组、流式分组及spill后归并出的分组：列中分别保存分组键和最终聚合值，AVG在这里根据sum/count计算，COUNT保留零与NULL参数的区别。Source的输出表达式及后续Projection合为同一个向量表达式DAG，不递归打开聚合的原始输入；并行Hash Build可直接消费这些列。Source的HAVING及后续Projection过滤按节点从输入到输出的顺序逐级筛选，NULL或false行不再参与更高一级条件和最终输出计算。结果压缩成同一列批次，保留运行时numeric精度、NULL和借用的文本视图；过滤错误在此前有效行被消费后报告，LIMIT停止时不提前报告后续错误。临时列与向量均计入CU子context及查询根workmem。输入累加批次与Source输出批次分别保存，避免输出时重新打开原始输入。spill读取等待保留尚未凑满的输出；并行Source退回串行时，先消费完已有输出，再切换到最终值列。表达式不支持或无法分配向量时保留原行接口；spill归并本身仍按原游标推进，未改为并行归并。

Hash聚合使用独立的紧凑查找表（每槽为原子状态和记录下标），聚合值连续保存。只清零查找表；创建分组的CU初始化该记录的全部值/count及NULL标记。负载上限为7/8，因此只分配对应数量的记录；Source和spill遍历有效记录，跳过空Hash槽的工作不再需要。扩容时重建查找表，记录缓冲通过统一分配器原地增长或顺序搬迁，避免逐个随机复制完整状态。两份缓冲和扩容瞬时占用均计入总预算；预留空间按替换旧缓冲后计算，实际分配失败仍沿用原spill路径。

查找槽的原子状态还保存 Hash 指纹（Hash 高位的一小段），碰撞时先比较指纹，再访问聚合记录和完整键。指纹相同仍比较完整键，扩容重建时保留同一计算方式。预算允许时，各 CU 使用自己的局部聚合表；表及其元数据全部计入根查询 workmem，沿用当前布局和更新函数。入场按实际剩余空间保留现有 spill 余量，不按 CU 数平分总预算；分配失败保留共享表，局部表满后的新键也可进入共享表。局部整数键按批次计算 Hash 并预取 lookup 和记录。

输入结束后，复用现有 CU 计算阶段并行合并局部状态。目标为空时，按键的 Hash 分配归属 CU；同一键只由一个 CU 更新，新查找槽仍原子发布。CU 读取原局部状态，不先生成一份分区副本。空目标的这轮合并若满，丢弃未完整合并的目标，保留原局部表，由协调端重新接续增长/spill；已有共享状态时使用受保护的并行合并，并保留各局部游标。SUM/count、MIN/MAX、NULL 和每值精度保持原语义，不提前计算 AVG。正常合并或取消后释放局部状态；结束的 CU 不再重复预留内存。新增状态和阶段仅在设备 SQL SO 中，PG、SNIA、固件及 AFDM 参数布局不变。

Hash Build的子依赖准备完成后，先按PG对该输入流水线的输出行数估计调整尚为空的构建表，再启动CU，减少从128行反复扩容和协调端补插。若输入为聚合Source及无过滤投影，则优先采用实际分组数；带HAVING、投影过滤或连接时不能把过滤前分组数当作精确输出。容量受实际剩余workmem约束，保留CU私有状态及两份排序额度；估计偏低或分配失败仍沿用原增长/spill路径，不改变查询总内存上限。

Source也可直接作为Hash Build、外层聚合或Sort的输入，不要求中间存在投影节点。源聚合完成后检查实际记录数；直接Source不足2048组时，沿用串行消费，不为小结果启动整组CU。较大结果继续用共享表和各CU游标推进；Hash Build、外层聚合和Sort分别使用已有并行Sink路径，不改变其语义。

## 节点与内存

- Scan/Projection：只解码父节点真正需要的列；投影、过滤、CASE、NULL 三值逻辑、短路、数值运算、LIKE、substring 和 year 在设备执行。仅用于 LIKE 的长字符串直接在扫描时判断，不先将所有文本放入字典。COALESCE与numeric除法也进入现有表达式列批次：仅左值为NULL的存活行求COALESCE右侧，文本保留视图；除法复用精确numeric原语，按值保留实际scale/dscale和错误位，不使用近似SIMD除法。
  Projection链及Hash/Merge/Index Join、Sort、驻留分组Source上的输出过滤复用表达式向量，先维护存活行选择，再计算输出；全部被过滤的批次直接继续读取。无过滤或全部存活时保留原批次布局，只有行数减少时压缩所需结果列，不复制完整输入行。
- Hash Join：按 PG 的左右输入 build/probe，支持 INNER/LEFT/SEMI/ANTI 和多键等值/剩余条件。表内按 PG 类型保存整数/date 的 4/8 字节值，numeric 保留完整 128 位，避免每列承担 32 字节的对齐填充。并行构建输入的 CU 按批预留行区并原子链接桶头，省去协调端逐行接收与再次构建桶链。表满时将未消费行保留在原 AFDM，协调端在本轮 CU 都暂停后扩容；阻塞子节点的父表仍从小容量开始，随实际输出增长。INNER 表扩容失败时，将已消费的前缀和后续输入按键分为四个分区，使用现有 SNIA spill 请求保存紧凑行；两侧 Heap 均只扫描一次。构建侧结束后重新检查实际空闲内存：若全部分区能驻留，按实际行数分配行区、单独为桶取二次幂容量，直接多 CU 扫描 Probe 侧，避免将它预先落盘；否则逐分区构建共享 Hash 表，各 CU 动态领取 Probe 块，偏斜分区超限时分批构建并重复读取该分区的 Probe 临时数据，不改用全表排序。其他不能采用此路径的形态保留原 Merge 回退。所有分配仍受查询根 context 和物理池约束。
  并行构建可直接引用Scan、Projection、Hash/Index Join、Sort及驻留分组Source输出的表达式列批次，按键批量计算Hash，再将各列写入紧凑构建行，不先生成AFDM中间行。满表时保留向量中的消费位置，将剩余行交给原协调端扩容/spill路径。已spill的分区Source和不支持的表达式仍使用已有行批次接口，保留各自的读取游标；不重新扫描源表。该路径复用原查询workmem和Hash布局，不增加AFDM或协议。
  残余条件复用表达式向量引擎：同一 Probe 行的重复键候选按至多256行求值，只收集条件所需列，并保留候选位置供多次输出继续消费。SEMI/ANTI先判断首候选；被拒绝后再按至多64个候选批量判断，命中立即丢弃余下候选，后续错误不提前报告。单候选、不支持的表达式或实际分配失败沿用逐行路径；批次临时区受同一查询workmem预算约束，连接结束即释放。
- Merge Join：分别排序输入，按键归并；重复键组可spill，匹配阶段保留输入、组内位置及SEMI/ANTI命中状态。匹配后的所需列按至多256行交给现有表达式向量，输出过滤、投影及相邻Projection不逐对解释；Hash构建退回Merge时也可继续使用该批次路径。残余条件只收集所需列，在当前spill块内对至多256个候选批量求值；SEMI/ANTI先单独检查首候选，未命中再按至多64个候选处理，命中立即丢弃余下条件结果。只在消费候选时报告其错误，不为提前取候选发起跨块读取。I/O或spill等待保留位置，批次排空前使用同一块取得所选右侧数据，避免重复加载；外连接补NULL进入同一输出表达式路径。单候选、表达式不支持或内存不足时使用原行适配接口；条件缓冲计入同一workmem，Merge结束释放。
  若输入已有显式Sort或Merge输出，且其排序键、方向及NULL顺序匹配Merge所需前缀，则直接消费；中间Projection/过滤只有直接保留对应键时才沿用顺序，不再将同一输入排序两次。流式聚合也复用这一顺序证明，只需分组键连续，不要求特定升降序。无法证明顺序、方向不匹配或Hash回退有尚待排序的前缀时，仍调用原排序适配器。不从索引或节点名称推断未传递的顺序信息，也不改变PG连接顺序。
- Index Join：复用 `index_scan.c` 的 PG12 整数 B-tree 下探与 Heap Tuple 解码，可在连接树多个位置出现。最多批量 64 个外侧键；要求保留顺序时一次一个键。缺页经现有控制记录和文件映射转换为设备内 namespace 读取，缺少映射时由 Guest 提交 LOAD。SEMI/ANTI 的列批次路径每轮从每个尚未命中的键取至多一个候选，一起执行右侧过滤和投影，消费端确认条件满足后立即停止该键；不支持列批次时保留逐候选消费。索引自连接复用当前扫描块中的 Heap 页，超出该块再读取，不建立跨查询缓存。索引游标按实际使用的槽延迟分配，单 CU 扫描只保留自身游标；共享索引上下文的额度按槽数增加。
  列批次消费端还会批量判断Join残余条件（等值键匹配后仍需判断的Join Filter），只保存条件和后续投影需要的列。右侧已过滤的候选不参与条件求值；每行错误延迟到消费时报告。批次临时区使用原查询workmem，连接结束即释放；单候选、无法导入的表达式或实际分配失败仍使用逐行路径。
  INNER/LEFT的存活候选用原列引用加选择向量传给输出表达式，不再复制成一份压紧的输出输入列。索引游标在输出消费完前保留原批次，随后才允许覆盖或释放；SEMI跨轮收集仍使用自己的缓冲。列视图保留每值的int128、精度和NULL，也可处理非连续或重复的选择位置。
- 有序 Index Scan：同一文件沿 PG12 B-tree 正向叶链收集 TID，批量回表，按索引顺序生成列批次。保持单游标供流式 GroupAggregate 消费；不把有序输入任意拆给多个 CU。沿叶链预读至多 16 页，Heap 在 PG 提供的正相关性大于 0.9 时预读至多 32 页，均受文件边界和原页缓存限制；无统计或相关性低时按需读取。额外 TID 列表仅为该游标分配，等值连接不承担这份开销。
- Index Only Scan：冻结镜像中支持前两个整数索引列，直接输出键和 NULL 位图，不请求 Heap 页。需要索引顺序时沿叶链读取；无需顺序时各 CU 动态领取互不重叠的物理页范围，只处理叶页，跳过内部页和已删除页。每个 CU 使用私有游标、页缓存和列批次；不支持的覆盖列仍走回表或原回退路径。
- Aggregate：扫描或等值连接输出上的 SUM/AVG/COUNT/MIN/MAX 可共同使用有界 Hash 表聚合，支持多键（包括字符串、numeric、NULL）及聚合参数的算术表达式；LEFT JOIN 补出的 NULL 不计入 COUNT(列)，COUNT(*) 则计入行数。每组按实际聚合数保存值/count（SUM/AVG 为精确和，MIN/MAX 为极值）；一次定位分组后更新所有聚合，AVG 在最终输出时才相除。spill 保存每个聚合的值/count，分组键数加两倍聚合数须不超过现有16列中间行容量，超出时保留排序聚合。整数和字符串字典 ID 按 64 位保存，NULL 使用位图；numeric 键保留完整精度。按 PG 分组估计和实际预算预留；阻塞子输入尚未完成或缺少合适估计时从 128 槽增长。并行输入可使用前述局部表和 Combine，预算不足时共享表保护并发更新；DISTINCT 仍对合并后的键精确去重，不能把各 CU 的 DISTINCT 计数相加。满表的原始行保留在 AFDM，当前 CU 都暂停后协调端扩容或 spill。聚合同时预留将启动的 worker 状态及 spill 空间；实际无法容纳时该段串行执行。需要 ORDER BY 时在聚合后排序；预算不足时归并部分状态，不重读明细。COUNT DISTINCT 的精确键投影先按“分组键＋参数”做 Hash 去重，再 COUNT 非 NULL 参数；不覆盖的形态保留排序去重。任意组合的 SUM/AVG/COUNT/MIN/MAX、分组和 HAVING 仍可走原有流式或外部排序聚合。
  已按键有序的输入可用列批次执行流式分组：先批量计算键和聚合参数，再按连续同键区间更新原累加器，不建立Hash表。COUNT(*)按区间长度累计，COUNT(列)仅在整批确认无NULL/错误时使用同一快速路径；其余情况逐值检查。当前组可跨向量、Sort Source及I/O等待继续累计，下一组首行保留在批次中。完成的组交给前述Source列批次执行HAVING和输出表达式，最终返回格式不变；DISTINCT、不支持的输入及尚未排序的形态保留原路径。所有新增临时列均计入查询workmem，不增加FDM或改变SNIA/固件协议。
- Sort/Limit：串行及CU局部Sink可直接读取生产者的表达式列批次，按列写入已有run，不再先逐行拷贝到中间结果缓冲。spill重入期间保留同一批次和输入位置，消费完成后才推进生产者；文本先保存为查询字典ID，宽numeric、动态精度和NULL保持不变。不支持的生产者继续使用原行输入，TopN沿用有界堆。source 跳过没有生成 run 的空闲槽，全空输入正常返回空结果；复用 `sort.c` 的有界工作内存 run 和分批归并，完整处理输入、OFFSET/LIMIT、提前结束与回收。
- CTE/InitPlan：共享 CTE 在设备计算一次并暂存，读者各自持有游标；标量初始化结果保存在设备参数数组。整数 IN/NOT IN 集合保留 NULL 和空集合语义。初始化完成的集合由CU只读共享，列批次只探测当前存活行并输出布尔值及NULL位；空集合上的NULL IN为false，含NULL集合中的未命中为NULL，NOT复用三值逻辑。集合探测通过设备SQL SO内部普通函数调用访问查询状态，不是SNIA完成回调；不复制集合或新增协议。扫描中的集合条件在查询列批次中执行，独立Filter CSF不访问该状态。当前仍仅支持整数集合。内存哈希表扩容失败后，初始化阶段保留当前行，将已有键和后续输入写为64KiB有序块，复用内部STORE/LOAD；列批次探测一次读块服务整批键，保留NULL、空集合及NOT IN语义。各消费者有私有读缓存与表达式继续位置，所有状态计入查询workmem。外部探测也接入标量投影及Hash/Merge/Index Join残余条件：等待LOAD时保留当前输入或候选批次，恢复后先完成该项，再推进来源。标量聚合先完成一行全部参数的求值，再更新累计状态；各批次消费端保留已处理的位置，避免重入时重复累计。

所有动态算法状态从 `libcs-workmem` 分配。通用查询先建立受 `max_memory` 限制的根 context；排序、索引子 context 同时计入根配额和全局池。Hash 表、run、归并游标不能放入 AFDM 来绕开工作内存上限。

通用计划创建排序时，初始额度取三者最大值：原计划保底额度、`根查询当前空闲内存 / (活动排序数 + 2)`、以及当前空闲扣除两份原保底余量后的空间（不足时按零处理）。活动排序指已初始化、尚未输出完毕的排序；两份余量供消费/归并及spill路径使用。这样保留原有可用额度，同时允许仍有大量真实空闲时容纳完整输入，避免仅按活动排序数量平分而过早spill。这是初始上限，不是实际预占，不扩大根查询限制。后续分配仍同时受排序context、根context和全局池约束，原spill处理实际空间不足；没有新增跨算子统一回收器或配置项。

`sort.c` 每个 run 最大约 1 MiB，spill 块为 64 KiB。内存优先保留 run，下一段超过预算才 STORE；归并 fan-in 受缓存预算限制，必要时分轮合并并释放旧 token。需要读缓存时优先 spill 驻留 run，避免驻留数据挤占缓存、每输出几行便重新读取整个块。每个 run 的归并头按实际投影列宽分配，与 token 一起计入 workmem，避免小预算被固定 16 列的描述占满。非 NULL 整数/date 和 run 内相同 scale 的 numeric 键使用精确 int128 radix sort，支持多列升降序并跳过常量字节；scratch 计入 run 所有者的配额，放不下时保留原有排序，不额外制造 spill。NULL、字符串和混合 scale 继续走原有精确比较。字符串比较使用字典；短最终字符串排序标记为 `UINT8_MAX`，不能与合法的 numeric 显示精度重叠。

正常完成或提前 Limit 后释放私有 context；取消/错误时 Guest 再提交 close，随后关闭当前 SNIA 会话，释放仍存活的临时 token。没有后台代理或独立设备执行进程。

通用树的 Sort Sink 可以直接消费 CU 输出的紧凑行批次：`qs_plan.ordered_rows=3`，`qs_result.begin` 指向本批尚未消费的位置；`ordered_rows=2` 仍表示普通定长行布局。这是设备 SQL 程序内部的布局约定，不是 SNIA 或固件协议。无界排序将连续行直接复制到 run；TopN 继续逐个维护堆。

当 Sort 直接消费并行流水线时，每个 CU 保存局部 Sort Sink，在自己的调用内生成有序 run，EOF 时排好最后一个未满 run；统一 Source 归并各 CU 的 run。局部排序 context 属于根查询，工作 CU 状态释放后仍然有效，实际总占用受同一查询 workmem 约束。启动前分配各槽的首个 run，分配失败则保留并行生产、协调端排序路径；此时协调端仍会保留生产 CU 输出至 STORE/LOAD 重入完成。空闲 CU 结束时释放未使用的 run，取消时清理整组 context。隐式排序和分区 Hash 回退仍使用原协调端路径；排序 Source 归并仍串行。

Sort Source 的结果以至多 256 行为一批交给投影及普通无分组聚合，不再为每行重新进入排序接口。向量表达式直接引用该批所需列；内部 `qs_vector_input` 的 `column_stride`/`row_stride` 表示相邻列/行之间的 cell 数，默认是列布局，也能读取排序结果的行布局，不需要先转置完整批次。可安全窄化的值放入连续向量以使用 SIMD，宽 numeric 和混合 scale 保留原值视图。整批消费完才允许 Source 覆盖或释放结果；STORE/LOAD 重入保留游标。普通 SUM/AVG/COUNT/MIN/MAX 的累计复用已有向量 Sink，AVG 保留 sum/count，最终输出时相除。DISTINCT、不支持的表达式及流式分组仍保留原路径。这些结构只在设备 SQL SO 内使用，不改变 SNIA、固件和 AFDM 布局。

## 单表列向量快路径和独立入口

原有实现保留供单表聚合及独立算子使用：

| 源文件 / SO | 主要入口和 AFDM 顺序 |
| --- | --- |
| scan.c / pg-sina-scan.so | `scan`：原始 Heap、计划、列批次、任务，必要时附字符串字典 |
| filter.c / pg-sina-filter.so | `filter`：列批次、计划、原始 Heap；生成 selection 并物化延迟列 |
| aggregate.c / pg-sina-aggregate.so | `aggregate_sink`：列批次、计划、任务；`aggregate_source`：句柄组、结果；分组时追加 spill I/O |
| sort.c / pg-sina-sort.so | `sort`：小结果、计划；`sort_sink`：列批次/行批次、计划、任务、spill I/O；`sort_source`：句柄组、结果、spill I/O |
| limit.c / pg-sina-limit.so | 小结果、计划；调整结果范围 |
| join.c / pg-sina-join.so | 原有独立连接链入口；PG 通用计划已由 plan.c 执行，不再用它选择连接顺序 |
| heap_count.c / pg-sina-heap-count.so | 诊断：原始页、计数；cparam1 为物理列数，cparam2 为有效字节 |

单表快路径按设备 CU 数、FDM、workmem 和输入块数选择最多 64 个独立 SERIAL batch，完成的执行槽立即领取下一块，不等待固定四分支轮次。Scan 按需输出 int64 列、NULL 位图、显示精度和 selection；numeric 可延迟到筛选后解码。`query_vector.h` 每批 256 行，复用列引用/常量和公共表达式，只为仍存活的行计算复杂条件。AVX2 支持比较、无溢出的加减和 int32×int32→int64；其他情况用精确 int128。没有浮点近似。

动态 Hash/聚合状态属于 workmem，FDM 仅作输入输出。单表入口 `profile.c` 包装计时，默认关闭；需要计时的 AFDM 放在 spill I/O 之前。通用树在 `pg_sina_plan` 入口累计整个 CSF，同时在 Scan/Filter/Sort 的调用边界计时；各 worker 结束后合并计数。还记录实际同时运行的 CU 峰值。算子分项包含在 CSF 总时间中，不能与总时间相加，也不对逐行递归反复计时。

```sh
cmake -S code/csd-programs -B code/csd-programs/build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build code/csd-programs/build -j4
ctest --test-dir code/csd-programs/build --output-on-failure
```

设备测试使用真实布局的模拟 PG 页与独立行循环校验 Join、NULL、重复键、外连接、精度、乱序多 run 归并、小内存 spill 和回收。它不模拟 NVMe 时间。实际 Guest 冷启动比较和使用限制见 [PG 扩展说明](../../apps/pg_sina_csd/README.md)。

TPC-H 验收只使用仓库 `tests/guest/queries/` 的 SQL，由 `tests/guest/tpch-test.sh` 执行；这里的 C/C++ 单元测试只校验算子行为，不替代 SQL 正确性和性能验收。
