## 已实现的列处理与分组优化

PG扩展继续采用PG选定的Join树。对于不要求分组输出顺序的单聚合，可去掉仅为分组提供顺序的Sort，并保留其投影；PG已验证由分组键决定的输出字段作为额外物理键保留，超出支持范围仍保留原计划。只接受由分组键、聚合结果和参数组成的HAVING。最终ORDER BY、DISTINCT及有界子查询的排序语义不变。

设备SQL程序将Hash Join匹配推进与结果投影分开，只收集后续表达式需要的列；Hash Join、连续Project、局部聚合可直接接续列批次。每个批次保留输入位置、匹配链及尚未完成的列数据，跨LOAD或spill时先完成请求再继续，避免重复领取输入。表达式批次当前为256行，与Heap解码窗口2048行、按FDM容量选择的读取块分开。

中间列保留每个值的int128、scale、dscale和NULL。统一scale且能安全表示的列使用窄向量及原SIMD路径；宽数值或混合scale使用精确路径，CASE保持所选值的实际scale。表达式错误到对应输入被消费时才报告，不越过LIMIT提前报告未来行错误。Join以聚合为左输入时消费最终聚合结果，不能借用其内部sink输入。

无过滤Scan作为Hash探测输入时，字符串payload先保留Heap字节视图，仅在Join命中、确实需要该列时才建立字典ID；字符串Join键仍须物化。父聚合遇到尚未完成的阻塞子节点时不按估计预占大表，待实际输入推进后增长；其他宽键分组使用PG提供的HAVING前基数，在真实剩余预算内分配。所有工作区计入既有查询workmem。

后续Index Join需要保留Heap窗口时，纯Scan/Hash生产链在推进窗口前交出已有结果。Index自身也能输出列批次，但以索引查找批次的游标及I/O接续为准，不能用远端Scan窗口代替其边界。

上述改动仅位于Guest PG扩展与 `csd-programs/pg_sina_csd` 设备SQL程序。FEMU固件仍只负责通用I/O、CU与设备图调度；SNIA接口、NVMe协议、femu_csd_args和应用配置均未新增SQL语义。
