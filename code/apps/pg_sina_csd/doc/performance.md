## 当前实现

- Scan/Filter对字符串直接引用Heap字节，SUBSTRING产生切片；仅过滤所用的列不进入字典，需要保留的结果才物化。向量参数保留int128与实际numeric scale。
- 保留PG选定的Join顺序。对不要求结果顺序、没有筛选条件、不能由索引覆盖的全量分组扫描，改用并行Heap扫描与有界Hash Aggregate；选择性索引和覆盖索引路径保持可用。不识别查询编号或表名。
- HAVING前的分组估计用于聚合表，过滤后的行数用于父节点。整数分组表在真实剩余预算内扩容；不足时走既有spill。驻留与spill归并输出都持续跳过不满足HAVING的组。
- 纯Scan/连续Projection输入的单聚合Hash Group直接消费表达式列向量，保留批次游标。共享表满时，仅未接收的行还原到既有AFDM适配器，由协调端扩容/spill后继续，不丢失或重复输入。
- 共享分组表的键在CU批次内不变，碰撞探测只读比较已发布的键，仅创建/更新目标组时加锁。向量中连续相同键先合并为局部SUM/count再更新共享表；检查至多16行的相邻键，没有发现重复就直接更新，不创建每CU完整哈希表。
- 向量表达式导入时从重绑定后的子表达式推导ADD/SUB/MUL/CASE的实际scale。PG通用numeric元数据不能直接表示计算结果的scale；精确数值、NULL和AVG的sum/count仍遵循PG语义。

这些SQL算法仅位于PG扩展和设备SQL程序，本阶段没有增加FEMU/SNIA协议、SQL固件逻辑或配置项。
