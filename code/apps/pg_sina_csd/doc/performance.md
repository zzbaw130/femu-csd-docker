## 本轮改动与Q22证据

## Q18：并行堆扫描与有界哈希聚合

参考 DuckDB 的哈希聚合路径，PG 扩展对不要求输出顺序、没有筛选条件、不能仅靠索引覆盖的全量分组扫描，选择并行 Heap 扫描与 Hash Aggregate。保留 PG 的 Join 顺序、选择性索引路径及覆盖索引路径。该选择根据计划属性作出，不识别 Q18 或表名。

PG 传入 HAVING 前的分组估计与过滤后的输出行数，分别供聚合表和父节点估算。设备聚合的整数键表可以在真实查询总预算内扩容；预算不够仍使用原 spill 路径。修复内存驻留及 spill 归并输出遇到不满足 HAVING 的分组就提前结束的问题。

## 长期目标仍在进行

目前尚未完成整个通用执行器的列批次接口：Join/分组聚合仍有逐行适配，局部与共享状态、Combine/Finalize覆盖和跨块持续执行仍需继续优化。完整轮通过证明当前这批SQL能加速，不证明这些实现要求全部完成。

保持PG负责SQL/计划编排、SNIA负责通用请求适配、FEMU CSD固件负责通用I/O与计算调度；SQL算法留在设备程序中。后续根据聚合与Join阶段证据推进，FDM仍保持64MiB；只有实际测量证明必要才测试256MiB。
