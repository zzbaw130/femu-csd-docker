# SQLerate 阶段成本与状态估计

本文记录 `adaptive-exec-path` 的规划模型，供论文方法描述与后续校准使用。模型在 Guest 的 PG 扩展中运行；设备 CSF、FEMU 与 SNIA 不参与成本规划。下面的字节数和时间都是规划估计，不能当作实测结果。

## 每 CU CPU 配额的自动接入

连接初始化复用现有资源查询 CSF：`cparam1=0` 返回 workmem 字节数，`cparam1=1` 返回每 CU 有效 CPU 比例的百万分比。启动器先把 `CSD_CU_CPU_RATIO` 转成 10ms 周期的整数微秒配额，再将归一化的实际比例传入 FEMU；设备 SO 读取该值，通过 SNIA CompValue 返回 PG。不从 Guest 的环境变量猜测配置，不增加另一个设备入口或逐查询资源请求。

默认启动比例为 `0.3333333333`，实际为 `3333/10000=0.3333`；`0.34` 对应 `3400/10000`。0 和 1 均不限额，查询结果统一为 1。PG 将此比例保存在连接资源快照中，所有设备 CU CPU 单价为 `host_cost_ms × csd_cpu_ratio / 有效比例`。已有 `csd_cpu_ratio` 是不限额 CU 的基础向量化价格，默认仍为 0.35；它不再承担把启动配额静态写入模型的职责。随后仍按原有串行、任务波次、合并阶段模型估计，不把 CU 数简单当成线性加速。

内部 NAND、PCIe、HOST CPU 和 HOST 元组转换不乘该配额因子。EXPLAIN 的 `CSD CU CPU Ratio` 及连接初始化日志可核对实际读取值。反比是 CPU 预算的成本近似，不保证内存/锁等待或整条查询延迟同比增长；本次自动适配不等于重新拟合基础 CPU、spill 或交付参数。

## 规划范围与数据来源

HOST/CSD 候选在 PG 的扫描、合法连接组合及上层 Path 搜索中比较，不再固定一棵物理树后才选执行位置。原始 HOST、原始 PG 优选树的完整 CSD 转换，以及安全 Query 改写后的共享搜索结果均保留为完整候选；见 [规划说明](planning.md)。强制完整CSD的多表计划复用相同的设备物理候选和价格，但最终只比较完整卸载候选；简单单表强制卸载保留既有快路径，避免无用的第二次PG搜索。以 PG 的过滤/连接输出行数 `plan_rows`、HAVING 之前的组数 `numGroups` 为起点，再恢复并行区域的全局行数、传播表达式分组范围及 Join 乘数约束；资源预留还可使用已验证外键域的统计容量上界。扫描输入行数读取 `pg_class.reltuples`；字符串 NDV、NULL 比例与平均长度来自 `pg_statistic`。缺少字符串统计时，NDV 暂用最多 200、平均长度 32B，均是明确的回退假设。不同列/关系的字典值可能重合，目前按其 NDV 之和估计，未假设跨表相关性。

HOST 使用 PG 原有路径成本模型，并在路径比较前修正扫描缓存成本；设备子树加上返回成本后换算为 PG cost 单位，使其上层算法由 PG 正常枚举。CSD 使用编译后的设备表示和实际算法重新计价，不把 PG 总成本统一除以 CU 数。模型输出统一为毫秒。filter-only 的既有计划改写仍复用逐节点增量估价，不受此次搜索改动影响。

HOST 顺序扫描的磁盘部分另以已有带宽约束：未缓存读取按 `min(PG磁盘估计时间, 字节/内部读带宽 + 字节/PCIe带宽 + 字节/内存复制带宽)` 估计，再依据实际缓存记录区分未缓存、仅文件缓存和数据库缓冲命中。仅文件命中仍按字节/内存带宽计复制，数据库缓冲命中去除 I/O；CPU、谓词、Join、索引探测和并行费用仍保留 PG 估计。这里没有将 I/O 除以 HOST worker 数，也没有更改原生 HOST 对照计划。该约束避免把 CPU 的 cost→ms 比例机械套到 NVMe 顺序页价格上；串行相加表示不额外假设三个数据环节重叠，是模型而非实测吞吐保证。

每个节点保留 H（HOST 节点、子树可混合）和 D（完整 CSD 子树）两种候选。H 可接收 D 的元组流并支付边界成本，D 不接受 HOST 中间结果。Hash Join 的 build/probe、Sort 的生成 run/归并、聚合状态的更新/合并/输出属于一个算子的内部生命周期，整体选址。不能把原生 Hash 的 MultiExec 状态当普通元组输出；需要 mark/restore 的原生 Merge Join 内侧同样保留接口。Partial Aggregate→Final Aggregate 只有在明确实现可合并状态传输时才可作为两个独立算子跨侧执行；本次不新增此执行能力。

## 并行阶段

PG 的参考点是 `costsize.c` 的并行扫描、Gather/GatherMerge、Hash Join 与 Aggregate：只缩短可并行工作，单独计入启动、传输、建表和最终处理。DuckDB 的参考点是 `physical_hash_join.cpp`、`physical_hash_aggregate.cpp` 和 `physical_order.cpp` 的 sink/local state、combine、finalize/source 阶段；这里按本项目实际运行时计费，不假设已具备 DuckDB 的全部并行能力。

规划器复用 `qp_parallel_boundaries` 和 `qp_pipeline_source`，与执行器使用相同的 pipeline 可并行性判定。只沿 probe/投影链传播并行性，不越过 build 边或阻塞边界。顺序扫描使用 4 MiB 输入块，FDM 不足时减少任务槽。执行器按列批次、控制、结果和 I/O 缓冲校验容量，多个独立设备流分摊 FDM。两个顺序扫描组成的 Hash Join 可用剩余 FDM 预读一批 probe 输入。probe 算子仍在 Hash 表完成后启动。

对一个阶段，令 W 为可分配 worker，T 为任务数，C 为单 CU 完成全部可并行工作的估计时间：

```text
waves = ceil(T / W)
parallel_compute = waves × C / T
schedule = waves × parallel_task_ms
stage_time = serial + parallel_compute + schedule + combine
```

T≤1 或 W≤1 时按单 CU 估计，不额外收费并行波次。扫描按物理输入块数估计任务，已完成 Hash Aggregate 的 source 按组数/向量容量估计。最后不足一轮的任务也占一个波次。该公式假设任务均衡，是尾部不满和调度已知条件下的估计，不声称预测了真实任务倾斜或所有共享锁竞争。

| 阶段 | 处理方式 |
| --- | --- |
| Heap/Index 扫描、投影、Hash Probe | 只有位于已标记 pipeline 中才按任务波次缩放。Probe 按输入行计取键、哈希及查桶。选择性较高的常驻整数 Hash Join 使用向量探测，先比较打包键，再对可能输出的匹配解包载荷 |
| Hash Build | worker 按构建侧行数估价键哈希、各输出列的编码及桶链接写入，随构建侧流水线缩放。常驻并行建表按估计容量预留，追加时已写入桶链接。标量或需要扩容的路径单独计串行重建 |
| 无分组聚合 | worker 更新局部状态，协调端按 CU 数×聚合数合并 |
| Hash Aggregate | 按实际布局判断局部表是否能够同时放下；放得下则计局部更新与分组分片合并，否则计共享更新及键更新串行争用项 |
| Sort | run 内比较可随已标记的上游 sink 并行；多 run 归并和最终输出单独按串行收费 |
| Merge Join | 无 Hash 的设备 Join 实际走 Merge；未证明有序的输入分别计排序，再计两路归并及输出表达式 |
| 已排序分组聚合、Materialize、Set | 按当前执行方式计费，不因配置了多个 CU 就自动缩短 |

CPU 单价复用 PG `cpu_tuple_cost`、`cpu_operator_cost`。向量运算、顺序 Heap 解码和 Hash Build 使用 `host_cost_ms × csd_cpu_ratio / CU 配额`。顺序 Heap 按每页一次页头检查、每元组一次行指针和一次元组头处理计价。无 NULL 元组的定长前缀按固定偏移访问，仅计实际投影的列。前缀之后按定长字段 0.25、变长字段头 0.5、写出投影值 0.25 个算子单位估价，计算至最后一个必需列。NULL 位图、数值转换及缓存局部性的差异仍是近似。专用融合聚合和普通顺序扫描使用同一规则。`parallel_task_ms`（默认 0.02 ms）只表示并行任务波次的调度成本。

融合 Scan/Filter/Aggregate 用编译产物的列标记估算 Numeric 解码，与执行器共用一次延迟解码判断。Heap 列定位始终按全部访问行计费。立即解码的列按全部访问行计入数值转换，延迟列按过滤后行数计入选择向量访问、引用检查及转换。谓词自身也读取延迟列时，用访问行数给这部分额外解码取保守估计。聚合按不同输入的累加器计入逐行更新，复用同一累加器的 SUM、AVG 和 COUNT(expr) 只计一次。

融合路径的简单整数或日期列与常量比较、符合窄向量条件的聚合输入算术按 AVX2 的四个 lane 估价。乘法保留额外的范围检查成本，分组查找和累加器更新仍按行计价。向量运算的成本是静态近似，实际数据出现 NULL 或超出窄整数范围时仍可能回退。

内部 NVM 带宽、PCIe 链路按共享总带宽计算，不乘 CU 数。内部读取与并行计算只在同一流水线的独立任务之间折算重叠，单任务的依赖及串行工作仍保留。Index Join 按已取得的键发起依赖读，其重叠单独使用并行探测工作估算，驱动 Heap 扫描继续使用顺序 LOAD 的重叠。HPCP/DCP 按链路工作未被前台覆盖的部分计费。

顺序扫描向 HOST 交付列批次时，HOST 按每行一次元组槽处理和每个投影字段一次读取估价。并行消费只缩短这段 HOST 工作。设备返回包的链路与读取请求仍只按一次共享交付计价。

## 状态布局与生命周期

估计实现位于 `src/planner/cost.c` 与 `cost_model.h`。容量增长和槽位大小对照设备 `plan.c`、`sort.c`、`dictionary.c`；这些是模型里的布局估计，不新增设备 ABI 或改变执行器内存配额。

| 状态 | 估计方式 |
| --- | --- |
| Hash build | 每列按实际压缩格式：PG int2/int4/bool/date 为 4B+1B NULL；int8 为 8B+1B；其他值为 16B+scale/dscale/NULL。每行再加一个 4B next 和两个 4B bucket。容量从 128 起按 2 次幂增长 |
| Hash Aggregate | 单整数键保留紧凑键格式；多键按整数/字典 ID 或完整 cell 区分；聚合值是对齐后的 cell+count。记录对齐到 16B，哈希槽 8B，最多使用 7/8 的记录容量，容量从 128 起翻倍 |
| CU 局部聚合 | 先估计一张全局表，只有全部 CU 局部表与全局表、两份最低排序工作集都能放下时才估计局部模式；最低工作集按公开run/窗口/向量/结果缓冲布局近似，私有元数据留余量，不再保留两份最大排序额度 |
| Sort | cell 记录加字符串独立载荷、长度字段；字符串平均长度沿直接列引用回溯到 PG 统计，计算生成字符串用 typmod/32B 回退；另计 run 描述、spill token、IO 缓冲。行数据与字典正文同时存在时分别计费 |
| Set/Materialize | Set 按最多输入行数的不同值和 1/2 装载率估计 16B 槽位；Materialize 按实际 cell 行估计。Set 未恢复所有表达式形态的精确 NDV，属于偏保守的基数上界 |
| 字典 | NDV×16B entry，2 次幂的 4B hash head、字符串正文；rehash 暂存新旧 hash head。正文/entry 按 64KiB 页取整，页描述暂按 48B/页估计 |
| 表达式暂存 | 每个活动执行副本按表达式数×256 行向量估计；不是 2048 行 Heap 列批次，后者在 AFDM。执行器按需分配，故这部分是预留估计 |

Join 先构建右侧，再在保留 build 表时消费左侧；Sort/Aggregate 在消费输入时积累自己的状态，随后释放上游状态并输出。模型分别维护“输出期间存活”和“EOF 后仍保留”（Set/Materialize）的状态，以及构建峰值，避免无条件累加所有已完成节点的工作集。小表初始分配与随后增长也分开处理。字典为查询共享状态，只计一次；允许随其他工作集增长被驱逐，没有新增固定 25% 字典配额。hash/sort reserve 来自现有执行器，不是规划器新加的内存限制。

这仍是静态生命周期近似：并行分支的瞬时分配、分配器元数据、表达式惰性分配、CTE/InitPlan 多消费者重用等可能影响实际峰值。估计不会覆盖或代替统一 workmem 分配器的硬限制。

## Spill 与串行归并

- **Sort**：按照实际 1MiB run（受 sort quota 限制时缩小）、每个输入的64KiB行窗口、含字符串时的额外64KiB文本窗口和可用内存估算归并路数，没有额外32路上限。先计必须驱逐的 run 写出与最终读回；run 超过 fan-in 时，再计完整中间归并的读写。CPU 分开计算 run 内排序和跨 run 的堆比较。
- **存在性 Hash Join**：单键纯等值、无残余条件、直接基表扫描构建侧时，利用列 NDV 判断增长屏障去重后是否能留在内存。初始分配按实际二次幂容量计费，增长屏障上的去重计入串行 CPU。并行整数构建若预计主表和去重缓存均能驻留，且 ANALYZE 的直方图与常见值落在位图范围内，则按预计非空行数减去 NDV 估计重复命中数。命中只计行访问和位图检查，首次出现仍计完整哈希构建，协调端计入桶和缓存清零。统计缺失时保留通用估价。实际范围外的键继续走精确哈希路径。
- **Hash Join**：INNER 的 probe 按匹配行和桶平均负载估算链上的候选数，计入链指针、载荷解包和键比较的标量 CPU 成本，仍受 CU 配额约束。INNER 沿实际 4 分区 Hash spill 计 build/probe 写出读回，超大分区按 build 批次增加 probe 重读。SEMI/ANTI/LEFT 容量不足时沿现有排序归并回退估价，复用已读入的 build 前缀。实际倾斜仍须实测校准。
- **Hash Aggregate**：容量不足时按 key/value/count 中间记录和输入量上界估计冲刷，再计外部合并 CPU；没有伪造精确的溢出组分布。
- **Set/Materialize**：按超出可用容量的部分估计一次写出读回。
- **字典**：可驱逐正文按共享剩余内存估计，一写一读是最低换出换入工作量；随机反复换入、rehash IO 放大仍不能由 NDV 单独准确预测。不能用这个下界认定实际 spill 放大已经解决。

## 可观察性与验证要求

SQLerate 的 EXPLAIN 新增串行 CPU、并行 CPU、调度、最终处理、字典工作集、FDM 预留及 worker 数；`CSD Stage Estimates` 按设备节点列出任务数、CPU、状态需求、估计常驻、可用额度和 spill。`Estimated Peak Workmem` 是常驻峰值估计，不能与完整逻辑工作集混为一谈。H/D 节点选择仍显示在 SQLerate 外层。未选中的设备候选保留汇总估计；原有强制 CSD 快路径不一定调用成本规划，不保证产生上述估计字段。调度按 pipeline 波次计一次，不对链中的每个 SQL 节点重复收费。

`tests/planner_cost.c` 检查单块不能多 CU 加速、不满一轮的开销、压缩 Hash 布局/容量跳变、分组表 7/8 容量边界，以及 64/256MiB 条件下内存增加可减少外排。集成验证只使用正式查询目录，冷启动核对结果与 EXPLAIN，不按查询编号修正模型。

论文实验还需要用既有执行 profile 比较：预测/实测阶段墙钟、协调 CPU、worker CPU、workmem 峰值及 spill 字节，并单列模型误差。构建成功、结果相等和模型预测准确是三个不同结论；在校准完成前不能声称 SQLerate 总能选中实测最快路径。

## 聚合状态容量与 spill 阶段修正

Q18 的第二个根因是 `lineitem.l_orderkey` 的采样NDV仅389264，实际约150万。按前者会误判多份CU局部表可以共存；合并真实分组时才溢出。现在单列、已验证外键可用其引用唯一键域的统计规模约束聚合状态容量。它是资源上界估计，不是“所有父表键必然出现”的断言，不提高HAVING输出行数，也不改变结果语义。强制CSD与SQLerate均在编译通用计划时应用这些估计，避免模式之间再次使用不同的执行布局。统计或FK不支持时保留原估计；很稀疏的FK覆盖仍可能使这个容量上界偏保守。

另沿编译表达式证明分组键是否全部来自某个Join的probe侧：若成立，分组数不能高于probe输入行数，不将一对多匹配产生的明细行数直接当分组数。此约束同样适用于Index Join，不需要修改连接顺序，也不依赖查询编号。它将Q18外层分组状态从约52万组约束到约13万组，消除了256MiB下最终Sort的虚假溢出预测；这里仍没有猜测HAVING最终只返回9组。

真实Hash Aggregate溢出时，模型按容纳组数估计刷出次数、部分key/value/count行、run生成及归并。无序键使用均匀占用近似；单列键依据PG的相关系数平方，在随机和物理聚集两端之间插值，避免对连续键反复高估重复部分状态。CPU单列计入部分行序列化、run比较、堆归并、逐行解码及重新聚合；协调端的行处理采用现有HOST标量CPU换算，不乘向量加速比，也不除以所有CU。其余向量工作仍保留原来的并行波次模型。

2026-11-02 补齐实际实现的两项区别：Hash 表以完整二次幂容量分配并保留 7/8 的密集记录位置，预算剩余部分可借给部分状态排序；`sort_init` 的深度配额是保底额度，不是上限。模型使用相同的 Hash 容量取整、借用剩余内存并预留两份深度配额，按实际可容纳窗口估算归并轮数。单整数键 run 按现有 radix 算法的计数、scatter 和 scratch 复制计费，不套用解释执行的 N·log(N) 比较；PG NULL 比例估计整段无 NULL 的概率，可能回退的部分仍保留比较排序费用。已经编码的部分状态复制按字节/内存带宽计费，不再次收取 Heap 解码与表达式成本；最终堆归并、重新聚合仍单独收费且不除以 CU。

Index Join 也沿 `qp_probe_scan` 检查执行器能否借用当前扫描的 FDM 块：必须是同一物理 Heap，且 probe 列可证明源自该 Heap 的同一索引键。物理相关系数平方估计聚集比例，并为跨块的匹配组保留缺失读取；无相关性、跨表或越过阻塞边界的探测不享受该抵扣。此项仅去掉已有 FDM 命中的内部 Heap 读取及对应填充，不去掉索引访问、候选解码和残余过滤。它不把历史查询结果当作设备缓存，也不按查询编号调整连接顺序。

Spill读写各按总字节的一半近似计费：读使用internal_mbps，写使用internal_write_mbps（当前默认100MB/s）。写值表示包含依赖请求与重入等待的有效吞吐，不是原始NAND写峰值；SF8实测中原1000MB/s初值明显低估外部路径，按完整CSD及Index Join图的墙钟、CPU和spill对照作经验校准。它不是SNIA资源查询返回的保证，换设备仍需校准。每64KiB重入I/O另按已有parallel_task_ms计调度工作；Sort按实际run、归并窗口和轮次计记录复制。无需新增设备命令、配置项或算子协议。

内连接需要分区写出构建侧时，估价还检查构建子树释放临时状态后的内存。若紧凑哈希表能装下，和设备运行时一样估计只写出、读回构建侧，探测侧保持流式执行。重载记录数按128取整，只有桶数组按二次幂取整。重载后的常驻表继续计入后续算子的工作集。内存仍不足时，计入两侧分区及大分区重复探测。

## 完整索引游标的访问量修正

## 独立扫描的交付与HOST并行消费

独立扫描已生成PG可直接引用的类型化列，不把其交付按重新解码Heap计费。CPU按真实运算、访问行数和输出行数计价，常量、列引用、已绑定参数不增加算术指令数。预计批次/续交数至少覆盖输入块任务，避免只用总输出行数除以返回容量，漏计高过滤率扫描的块末尾工作。已有result_batch_ms默认0.25ms，来自当前系统读取及续交各约0.14ms的细分记录；PCIe字节成本另计，后续平台仍应校准。

设扫描各阶段的总I/O时间为I、按现有任务波次折算的CU时间为C，有效参与者L=min(CU数,任务数)。独立扫描估计 I+C−min(I,C)×(1−1/L)，不把CPU简单除两遍。单CU或单任务仍为I+C，保留较短阶段的填充/排空份额。完整设备树沿实际pipeline source计算读算重叠；HOST返回与内部列块的物化分别计价。

无序顺序扫描有多个任务槽时，回调逐个读取结果包，当前槽等待读取完成后才能继续，其他槽可继续 LOAD 或计算。每个输入块独立发送最后一个不满的包。模型按可并行任务槽计算交付与设备工作的重叠，保留较短阶段的一个槽份额；共享 PCIe 仍同时计入结果和缓存填充。HOST 元组转换单独计价。下游 Join 的重叠抵扣只使用独立设备生产工作，已经付费的读取、续交等待和 HOST 转换不再抵扣。

在HOST连接处保留独立输入候选，防止PG在扫描层提前剪掉异构重叠机会。设原节点成本T、原/新输入成本差Δ、该HOST节点自身CPU为H、新CSD输入运行时间为D，则候选总成本为 max(新启动成本,T+Δ−min(H,D))。本实现只在直接父Hash/NestLoop比较，Hash分批、参数/顺序不兼容和私有重放形态不抵扣；不声称对任意多阶段并发图求解精确的资源关键路径。输入CPU与上层HOST CPU用不同执行资源，Join的build/probe状态仍同在HOST。

HOST Index Join 的重叠抵扣使用 PG 去除 I/O 后重估的连接 CPU。参数化探测的冷缺页依赖已交付的外侧键，并与设备 LOAD 共享存储资源。保留 PG 按缓存驻留修正后的冷缺页费用，同时检查两侧合计的存储及 PCIe 服务下界。这样全热探测仍可用 CPU 重叠，冷态同步探测也会影响候选排序。

HOST B-tree 的缓存折扣作用于 PG 已摊销重复访问后的索引叶页读取量。对这部分读取量只应用一次查询前的驻留比例，shared_buffers 命中去除 I/O，仅文件页缓存命中保留复制开销。B-tree 下降、比较、缓冲引用和元组处理的 CPU 价格沿用 PG。Heap 保留原有估价。

当前决策保持纯统计模型：估价使用现有PG统计、设备物理属性和缓存驻留记录，不执行Join采样，不将验收实测行数写回规划器。现有单表统计无法完整表示跨表谓词相关性；Q3仍有基数及路径误选，作为已知精度限制明确报告。

同一基表的两列直接做有序比较时，SQLerate 使用 PostgreSQL 的直方图、常见值及 NULL 比例估算选择率。该估计假定两列独立，缺少可用统计时沿用 PG。修正后的基数用于基表 Path、参数化扫描及后续 Join 搜索。对于使用这些基数的 HOST Hash Build，以 PG 的元组布局和分批预算检验基数上界是否会超出内存。如果点估计原本就需要分批，沿用 PG 已计入的费用。如果只有上界会超出，按估计区间超出预算的比例计入临时页读写和分派 CPU。这个比例衡量对基数误差的敏感度。所有并行 worker 的临时页共享同一个 I/O 路径，按总页数计费。原始 HOST 候选与共享搜索中的 HOST Join 都纳入这项修正。

PG 已估计多批的 Parallel Hash 保留原有的正常分批读写费。对连接产生的构建输入，以估计行数至其两倍作为一次扩批的敏感区间，并结合已有的列比较不确定性。用 PG 的批次预算查找首次跨越当前批数的行数。按超出预算的区间份额计入一次扩批，只收取已分批建表数据的读回和重写、移出内存批次的数据写入，以及复用已有哈希值的重分区 CPU。额外费用在最终 HOST 与 CSD 候选比较时计入，保留 PG 对多批 Hash 的连接枚举顺序。探测侧仍按 PG 原模型计费。区间份额是估价近似。

当同一基表的多个列间比较共享列时，例如 `a < b AND b < c`，这些比较保留 PG 的估价。单列统计无法提供共享列在两个比较中同时成立的联合选择率，分别替换每个比较的估值会把两次独立修正相乘。孤立的列间比较仍使用现有直方图估价。

对于无序 HOST Semi/Anti 索引探测，分别估计会触及的 Heap 页和索引页。按各自的 shared_buffers 和文件驻留比例估算其中的冷缺页，并以设备随机读服务、PCIe 传输和复制时间约束 PG 的缓存折扣。探测范围和驻留页之间的实际重合仍是估计，HOST 索引比较 CPU 与 PG 的提前结束规则照常计费。

## Semi/Anti 索引连接的缓存扣费修复

原生HOST候选的缓存修正曾将一次完整内侧索引扫描的价差乘外侧行数。PG对SEMI、ANTI和inner_unique连接可能只读到第一个匹配，原连接成本没有包含这些完整扫描，因而产生过量扣费，Q4最终被截成0ms。

现在在原生Path阶段，保留同一索引的缓存后startup/total价格，调用PG原有initial_cost_nestloop/final_cost_nestloop重新估价，仅替换内侧输入价格；PG的match_count、匹配比例、提前结束、重扫与CPU费用均保留。临时价格在正常及ERROR路径均恢复。将差额用于选中原生计划的缓存修正，不再在这些节点重复乘完整内侧价差。只处理有真实缓存价差、内侧为索引扫描且可能提前结束的连接；没有额外设备请求或运行SQL采样。

## 参数化索引、短路过滤与扫描CPU预算

## 缓存停止与流水线估价的一致性（2026-11-02）

HPCP/DCP是可选的填充目的地。连接的现有驻留位图表明全部目标已驻留，或两个目的地均达到各自准入限制时，PG通过FEMU插件已有vendor配置暂停当前执行的接收。插件使用已有RX_STOP解除设备接收环；它不再生成带缓存标志的新图，已执行图也因接收环解除而停止登记和发送。仍在复制的块先完成或撤销引用，之后不会继续持有FDM。下一查询重新判断是否需要填充，不能永久关闭。仅DCP满、HPCP仍可接收时继续HPCP，反之亦然。32MiB初始化接收池继续保留；“停止开销”指不再产生新的DMA/接收块工作，不指归还初始化池或抹去此前开销。

成本端只对未满足的目的地估计可选PCIe填充量：`max(HPCP开启 ? 1-file_fraction : 0, DCP开启 ? 1-shared_fraction : 0)`。两个缓存的页面集合可能不同，此处采用保守的集合并近似。大型顺序Heap扫描使用与执行端相同的DCP bulk-read目标。观察到该目标已满足时，DCP不再为这次扫描增加预计传输，仍按文件页驻留量估算HPCP。索引访问继续按实际shared_buffers驻留比例估算。CSD输入始终计入内部NVM→FDM读取。

流水线内的LOAD与计算对单任务仍有依赖，但不同任务能重叠。模型沿已有pipeline source归属累计I/O和并行CPU，再按`min(I/O, CPU) * (1 - 1/有效CU)`扣除重叠一次。Hash build归入build输入；分组sink归入其输入；协调、combine及依赖驱动的spill不参与抵扣。此前只为独立扫描计算重叠、对完整设备算子链简单相加，导致全CSD候选被系统性高估。没有改变实际任务调度，也没有降低spill带宽价格。

Sort沿执行器实际规则检查直接且唯一的LIMIT消费者，估计TopN保留的`limit+offset`状态及全输入比较成本。状态能放下时不按完整输入虚构外排；放不下、共享/物化引用、谓词或无界时仍估完整Sort。估价和执行共用边界判定，避免选中之后才发现使用另一种实现。

对于带残余谓词、同一键域的ANTI连接，PG独立性估计有时退化到一行。自适应HOST搜索现在与已有设备模型使用同一DuckDB半/反连接20%不确定性回退，并同步更新PG提前结束的匹配比例；只在已验证同表列或单列FK键域时使用，不改变原生host-only基准。它仍是统计回退，不能证明真实选择率。

重复索引探测的PG I/O价格已经包含跨probe复用。观测缓存和这种复用不能对剩余I/O连续打折：分别从单次探测估计出发，取`min(PG重复探测I/O, 单次探测I/O的驻留修正)`。CPU全部保留，不因shared_buffers命中被额外削减。Q21诊断还表明跨表连接行数本身可相差数十倍，此修正不宣称解决所有基数误差。

## Join分组上界、扫描与索引早停（2026-11-02）

本轮只修改估价及估计行数传播，未修改SQL、算子执行实现、设备资源、默认速度参数或按exe_path区分物理算子。参考本地DuckDB统计传播与等值列绑定的思路，继续使用PG现有统计，不做Join采样。

- 分组键若可证明全部由某个Join输入决定，分组数以该侧估计输入行数为上界，支持probe/build两侧。INNER等值连接的两侧键等价，允许把一侧键换到另一侧做来源证明；LEFT的右侧可能新增一个NULL组。参数化Index Join的内侧行数是每次探测行数，不能作为全局分组上界。Sort无过滤时直接继承输入逻辑行数，避免对已经收紧的子节点再次按比例折扣。
- 表达式CPU只统计运算，列引用、常量、参数及已计算的聚合引用不重复收费；聚合更新单独计费。候选属性用负column的Q_AGGREF记录未编码运算，不能误认为全部是免费引用。轻量候选没有恢复完整指令编码。融合/通用设备链都采用同一计数规则。
- 所有扫描都复用scan.c的Heap walker，在最后一个所需列停止。估价的Heap前缀比例因此也对内部扫描生效；返回PG原值和内部cell的物化仍分别计价，没有把返回格式优化套到内部单元。
- 纯等值SEMI/ANTI Hash的去重容量不再仅凭低采样NDV断言“放得下”。复用已有单列、已验证FK键域的状态容量上界；它不用于提高选择率，也不宣称子表覆盖全部父键。稀疏FK仍可能使容量估价偏保守。超过容量时，只有INNER走分区外排，SEMI/ANTI/LEFT按设备实际路径计排序、复制、串行归并及spill；已保序的probe输入不重复排序，保留build前缀仍须排序。
- 本地过滤后的Index Semi/Anti可以在首个合格匹配停止。设每键候选数N、本地条件通过率p，预计访问数为`(1-(1-p)^N)/p`，p=0时为N，p=1时至多1。p来自现有IndexScan输出估计与键NDV，不使用验收行数；关联残余条件或缺少统计时保留完整候选访问量。Heap页访问继续使用相关性与有界索引缓存模型，预取和键倾斜不因此变成精确可知。

Q3的来源证明之前只识别probe侧，还漏掉INNER等值键可换到build侧：分组中的lineitem订单键与orders订单键等价，因此整组键可由已过滤orders输入决定。当前组数从2599962收紧到1219592，预测聚合状态从620757120B降到310378624B，spill从671575784B降到447090718B。仍高于上轮实际90931组、实际spill=0：剩余差额来自订单日期与明细发货日期的跨表相关性，普通列统计不能精确表达。本轮Q3只检查正式EXPLAIN与来源证明组件，不重跑Q3性能，不宣称统计问题全部解决。

## SF2定向修正：索引、混合流水线与聚合状态（2026-11-02）

设备内部重复读与主机缓存填充分开定价。随机Index仍按有界游标缓存估计重复缺失；填充按页面唯一占用的统计近似估计字节，不能把每次重复内部读都当成新增DMA。Index登记/提交固定工作按最多64页的实际批次估计，顺扫按输入块计，取消此前每个8KiB页单独加2µs所造成的数量级偏差。不是删除填充费用，也不改变填充开关或准入策略。

有序访问需证明探测键源自驱动Heap扫描，并用该列的相关性平方折算相邻Index页复用；Heap复用再乘目标索引键的Heap相关性。来自Hash构建侧的键不能借用外侧扫描的顺序。局部性由驱动键来源决定，SEMI/ANTI提前结束改变访问数量，不自行打乱探测键顺序；同一Heap有多个别名、无法区分来源时不借用该有序性。匹配单键外键且没有Join残余时，CPU访问量复用PG的Join fanout；有局部扫描过滤时按已有选择率还原过滤前候选量。外键域容量不当作实际NDV，也不把最终过滤后的行数当作全部解码次数。

HOST保留原PG物理树的候选只修正已观测缓存与匹配FK的CPU，不重新替换其已有I/O/rescan价格。共享搜索的参数化索引则按实际外侧行数重估循环次数。索引缓存命中以PG行数、相关性推导的访问工作集为分母，结合该关系实际驻留页量估计，避免单纯以整表未驻留比例收费；仍保留PG原缺失估价作为上界。这是统计工作集模型，不能识别同一关系中不同谓词访问集合是否重叠，不代表缓存记录新增了页面，更不保证驻留页面一定都属于当前查询。

扫描下推与HOST Index消费的重叠，使用PG `initial_cost_nestloop`/`final_cost_nestloop`对无I/O的私有Path重新计CPU，保留SEMI/ANTI提前停止和rescan规则。已经获得重叠减免的设备扫描交付路径，在后续Join hook重访时不再次从头计费，否则会覆盖已有减免并剪掉混合路径。没有给filter-only或SQLerate新增专属算子。

逻辑分组上界在INNER Index Join与Hash Join下使用相同的等值键关系；Index的参数化右侧仍不能作为全局行数上界，外连接NULL扩展也不套用等价规则。可并行Hash Aggregate超过预算时，模型对齐设备现有的私有局部表、radix分区流和多CU Source，按实际3/5表预算、二次幂容量、64KiB流块及Source工作区估计；只有不满足该路径条件时保留串行PartialSort估计。没有修改实际内存配额或spill算法。HAVING尾部和跨表相关性仍受PG统计限制，未采样或按查询编号修正基数。


## 设备索引缓存与小块读取定价（2026-11-03）

设备确有索引缓存：`csd-programs/pg_sina_csd/index_scan.c`中每个游标有128个8KiB槽，Index与Heap共用，CU之间不共享。它是AFDM中的游标I/O缓冲，不是PG的shared_buffers，也不是查询间保留的整索引缓存；只有根页受保护，其余页会随轮换被驱逐。旧估价计了叶页与Heap缺失，却把B-tree下降近似成每个副本只读一次，遗漏中间层在轮换中的重复加载。

现在按实际并行游标拆分探测量，保留根页一份，其他Index层与Heap按有界缓存估计。中间层既计不同页，也按叶页/Heap插入量估计轮换后的再读；一层能放入其统计缓存份额不代表其永久固定。有序键使用列相关性平方混合顺序与随机两端，同一Heap多别名无法证明来源时退回随机估计。这仍是均匀访问与轮换近似，不是精确缓存模拟，不知道每个查询真实热键和页面序列。

顺序带宽不能表达大量 8 KiB 请求的 FTL 服务开销。`pg_sina_csd.internal_read_iops` 默认 200000 次/秒，表示设备内部小块读的聚合有效服务能力。Index Join 和不进行连续 Heap 预读的完整索引游标使用以下估价。

```text
read_ms = max(缺失字节 / (internal_mbps × 1000),
              缺失页请求数 × 1000 / internal_read_iops)
```

同一读取阶段取带宽和 IOPS 两个约束中的较大耗时。带宽与 IOPS 都是设备聚合能力，缓存命中的页不计入 I/O。当前 FEMU 在 SF8 实验环境用 16 路并发、只读 SNIA LOAD 测量 1 GiB 文件，三轮中位数为 3418 MB/s（每批 2 MiB 连续读取）和 200552 IOPS（每批 32 个随机 8 KiB 页）。据此将 `pg_sina_csd.internal_mbps` 默认设为 3500 MB/s，小块读默认设为 200000 IOPS。这两个值包含请求提交和设备软件服务开销。更换设备或 I/O 服务线程配置后应重新校准。

候选回归另定位两项相关错误并一并修正。扫描的`cpu_tuple_cost`是访问每条tuple的固定开销，不能乘“最后所需列/总列数”：即使只取前几列，页内偏移、行头等固定检查仍执行。现在保留完整固定项，投影与表达式仍按所需列计费，未改变真实算子的列裁剪。HOST工作集抵扣不再跳过每次返回至多一行的唯一键IndexPath；继续用PG原有NestLoop重扫和提前结束计价，不额外削减索引CPU。

`pgSinaPlannerCost`覆盖中间层缺失、根页排除、缓存容量/轮换、局部性及IOPS/带宽两种瓶颈，并对1/2/4/8倍输入检查同一公式。公式尺度检查不等价于对应SF的SQL验收。本次仅SF2在线，主要冷态三轮路径保持，热Q5/Q21改选HOST；Q7/Q8和部分混合候选仍有误差。详细测量及SF2 Q15既有编码错误见[本轮报告](../../../../results/tpch-sf2/index-io-model/report.md)，不以旧SF1/SF8成绩代替新模型验证。

本轮额外Q20对照发现，调高Index费用后会转向先对大量输入更新共享聚合表的树。旧的共享表争用项只包含键比较，漏掉分组记录的访问与发布；该树估计仅便宜约20ms，实际慢约230ms。现沿用既有共享更新的串行争用近似，补入每条输入的tuple记录访问基价；这不是断言每条记录受一个全局锁串行执行。私有局部表不加此项，radix路径移除完整同一项，不能给不共享的更新错误收费。未改变实际算子、共享锁或内存配额；最终回归和该对照分开记录。

## FK连接CPU、类型化返回与流式混合候选修正（2026-11-03）

原生HOST的普通INNER索引连接现在同步扣除`outer.rows*(旧inner.rows-修正后visits)*cpu_tuple_cost`。已有FK证明要求单键、无Join残余，visits不变时减免为0；Index I/O、根到叶比较、PG rescan及SEMI/ANTI早停继续沿原实现。共享搜索的无I/O消费CPU估计也恢复相同visits，避免调用PG cost_index后行数回到未经FK修正的值。

### SF4：Limit融合与冷热计算成本分项修正

Limit直接消费设备子树时，HOST Limit在PG模型中几乎免费，两个候选可能仅差微秒而保留较早的HOST路径。现在仅对**同一个设备子输入**、设备端可表达的Limit，在PG通常使用的1%估价容差内优先融合；不将HOST计算的输入移到设备，也不禁止真正有HOST下游计算的混合计划。实际成本数值仍保留，不用改小报价实现选择。设备Limit只按实际访问的`min(input_rows, offset + output_rows)`计游标推进和输出表达式工作，不按整个排序输入计价。底层Sort仍处理所有输入；估价与执行统一使用`qp_sort_bound`判断TopN，包含OFFSET，共享/CTE/参数消费者需要完整排序时不应用上界。

HOST顺序扫描保留PG原有表达式、连接、并行和tuple处理价格，但增加对`allvisfrac`的具体工作修正：PG `heapgetpage`在全可见页上跳过逐tuple的MVCC检查，只检查一次页标志。用一个`cpu_operator_cost`近似一次检查，扣除全可见范围内`tuples - pages`次检查，再按该Path的PG参与者因子分摊。只修正SeqScan，不重复减免PG已经计过可见图收益的IndexOnlyScan。它在冷热态都成立，不是热态统一折扣；页缓存及shared_buffers继续只修正各自实际I/O/复制工作。

设备简单AND过滤按`filter.c`已有的selection执行方式估价：没有布尔中间向量时，不再计每个AND的标量解释；支持AVX2时整数/日期比较按四个64位lane计，延迟解码的Numeric比较仍按标量计。只有简单列与常量比较适用；OR、LIKE、CASE、复杂表达式等保留原价。候选属性记录与最终IR都执行相同判定，阶段日志同时记录原表达式数及实际计费的`physical_ops`。

设备Hash Join另外按输出行数×输出列数计单元/NULL槽填充，而不再把不同宽度的输出都当作一次tuple访问。这部分内存及控制工作使用既有普通单元操作价格，向量CPU比例只作用于原有表达式/键计算；不新增全局倍率。以上都是现有运行步骤的工作量代理，不能当作硬件周期的精确测量，也不按SQL编号或SF配置取不同系数。

复杂谓词也可能先被简单AND条件筛选：属性记录保留既有PG谓词根的引用，使用`clauselist_selectivity`估计这些前置条件的存活率，计为“前置比较工作＋存活率×完整表达式工作”。完整表达式仍可能重算前置条件，因此没有把它们再次扣除；当前置条件选择率为100%时模型反而增加这项额外工作。只提取顶层AND中的整数/日期列与常量比较，不穿过OR，不将延迟Numeric列当成可提前筛选的列，也不采样数据。

B-tree下降、游标线性缓存标签查找以及共享Hash分组表逐行更新均为串行指针/控制操作，不使用表达式的向量加速比；仍依据实际任务数/CU分摊可并行的游标工作，共享更新保持串行。分区聚合避开共享更新时也撤销相同的费用，不能重复收费。以上价格由现有PG CPU单价换算，未增加按模式、查询或数据规模选择的系数。

原始相关Query的PG树不支持设备编码、但去相关后的Query已经可执行时，另保留一次**PG对去相关Query的原生物理计划**作为设备候选。它使用相同的设备属性/成本/最终编码流程，与混合Path搜索结果比较；没有重新实现连接顺序优化器。仅在原生设备候选缺失且确有Query改写时增加这次PG规划，已有原生候选的普通查询不付出该开销。原始HOST候选仍保留；选中计划的`Placement`用`query=rewritten PG physical tree`标明来源。这个补充避免HOST/CSD混合搜索提前剪枝后，遗漏PG本来会生成的较优设备布局。

### SF8 sel0.1 的扫描与分组估价修正

简单 AND 过滤沿用设备 Filter 的顺序。先计算已解码列的 SIMD 前缀，再用 PG 的 clauselist_selectivity 估计存活比例，后续 NUMERIC 解码和比较仅向存活行收费。保留其他投影表达式费用。复杂表达式继续使用既有回退，不按查询编号选择估价规则。

单列分组若直接来自扫描或保留行身份的 Projection/Sort，并且该列是有效复合主键的首列，则利用主键后缀各列的统计 NDV 乘积估计同一首列值的行数上限。输入行数除以后缀组合数形成分组数的统计下界，必要时按 PG 原 HAVING 比例传播输出行数。它依赖后缀统计是否具有代表性，不是约束证明的真实 NDV。已有 FK 引用域仍只用于状态容量上界，不作为表覆盖率。未修改 PG 统计或正式 SQL，也未采样 Join。SF8 的 Q18 中，l_orderkey 的采样 NDV 为 421110，l_linenumber 的 NDV 为 7，而明细表约有 4799 万行，该规则纠正了过低的索引探测次数估计。

标量扫描和融合分组聚合允许每个物理 CU 保留两个独立任务槽。一个槽等待 LOAD 时，其他槽可以计算。CU 数量保持设备查询结果，全部槽的输入和向量仍须通过现有 FDM 容量检查，融合聚合的状态估价也按槽数计算。

外排排序在消费首行之前，根据实际分配结果选择初始 run 大小，分配受限时按完整 I/O 块缩小。已经建立的 run 保持原尺寸，并复用既有驱逐和归并流程。该修改处理并行算子造成的碎片化，保留原总内存限制。64 MiB 碎片化回归、64 MiB 外排排序及分区聚合回归已通过。冻结版本全量记录结合 Q1、Q6、Q18 修复后的三组五模式针对性复验，66 个查询与缓存模式组合中 64 个进入 10% 门槛；修复后的 165 次正式查询全部结果一致且 FDM 回收检查通过。Q21 热态和 repeat 仍超过门槛，按现有规则单列跨表与别名相关性误差。原始来源和逐查询结果见 results/tpch-sf8-sel0.1-final-audit/report-after-fixes.md，未将汇总称为再次全量测试。
## SF8 sel0.1：参数化索引工作集与候选量一致性（2026-11-04）

参数化 B-tree 等值探测的 HOST 工作集与 CSD 候选量，复用已有复合主键尾列 NDV 统计约束。它用于修正“单列 NDV 给出每键约 114 行，而复合主键尾列组合估计只有 7 种”的矛盾，不改变 PG 统计表、查询基数或算子实现，也不将 FK 容量当作实际覆盖。HOST 仅对首列完整等值、非 lossy 的索引条件使用约束；范围访问不套用。尾列 NDV 仍是统计估计，不是新增的硬件能力或精确频率观测。

HOST 的 SEMI/ANTI 缓存访问工作集计入首次匹配早停，包括完全不匹配的情况。含有未被索引条件覆盖的外侧参数条件，或仍有 Join 残余时，不假设这些条件必定成功；保留原保守访问量。缓存只降低 I/O 价格，不删除 B-tree 下降、缓冲 pin/比较和文件缓存向 shared_buffers 复制的开销。

本轮只通过既有入口测 SF8 sel0.1 Q4/Q21：五种模式，cold/warm 各三次、repeat 五次，共 110 次正式查询；结果全部一致，组末 FDM_USED 为零，已有 pgSinaPlannerCost 组件通过。Q4 warm 三轮均为 orders 扫描下推、HOST 索引连接/聚合/排序，SQLerate 中位数 1910.828 ms；repeat 路径为 CSD×3→混合×2，累计 12669.335 ms，比修改前冻结记录 15041.9 ms 低约 15.8%，比本轮最快固定可比模式 filter-only 低约 12.6%。不直接拿另一模式自己建立的缓存判定第 2/3 轮是否误选。

## 流式扫描与 HOST 索引消费估价（2026-11-05）

直接由 CSD 基表扫描供给 HOST Index NestLoop 时，HOST 可以在后续扫描继续运行期间读取索引和表页。现在保留 PG 的 CPU、重复探测与提前停止估价，将可独立执行的消费端 I/O 也纳入重叠；同时以两端合计的内部读取、出站 PCIe 服务量和启动依赖约束下限。仅有直接扫描的普通 INNER 边界具备所需资源分项，SEMI/ANTI 和经过其他 HOST Join 的链继续保留原 CPU 重叠策略，不假定所有阶段均可隐藏。

参数化索引重计时，不应让纯设备扫描的 Heap 占用 HOST shared_buffers 的容量份额。对直接设备扫描，排除其 Heap；启用 DCP 的小表或非普通关系仍保留容量竞争，大表按现有 bulk 策略保留 32 页以内的环。只有其余 HOST 基表加当前索引能放入 NBuffers 时，才以该竞争范围调用 PG cost_index；不更改全局 effective_cache_size，也不把它当成实际空闲内存。直接扫描键与索引 Heap 键的列相关性平方、预计访问页密度用于随机/顺序价格插值；稀疏探测及无法证明键来源的中间结果不获得额外顺序收益。文件缓存到 shared_buffers 的复制费不随磁盘价格插值而减免。

当前 FEMU 的 nvme_charge_link 对整块 DMA 预留共享出站链路时间，扫描结果的小型读取可能排在 HPCP DMA 后面。每个扫描流等当前结果读取完成后才提交下一次读取，因此同一填充 DMA 最多阻塞该流一次。按均匀到达近似，预计等待为 `min(结果批次数 × 平均 DMA 服务时间 × 填充链路占用率, 填充总传输时间) / 2`。平均服务时间由预计填充字节、输入块数和实际扫描块上限推得，填充链路占用率由填充传输时间除以生产端时间并限制为 1。这部分等待与 HOST 消费 CPU 分开估价。无待填充页面时此项为零。

SF8 sel0.1 Q12 的定向复验发现：原先最快的 filter-only 不带填充，不能据此断言带 HPCP/DCP 的混合路径一定快于带填充完整 CSD。混合路径实际只返回约 7 MiB，却伴随约 7.37GB 填充 DMA，其结果读取累计约 1s；无填充扫描的对应记录约 150ms。忽略这部分排队会产生新的误选。最终测试及保留限制见[本轮报告](../../../../results/q12-mixed-cost-fix-20261105/report.md)。本次不修改算子、执行调度、缓存开关或设备资源，不以模型修正宣称完整 CSD 的实际索引性能已经改善。
