## 路径和性能差距

- **Q7、Q21 已通过之前缺失的条件。** Q7 四组 repeat 均为三轮全 CSD，单轮约 4.10–4.18 s。Q21 四组 warm 均为全 CSD，6.311–6.430 s，比固定 CSD+ 快约 15.9%–18.0%。设备计划先做 orders Hash Join，再做两次索引探测，读取的索引 Heap 元组从约 247 万降到 110 万。四组 repeat 也均为全 CSD。 [Q7 repeat 样本](sel0.1/repeat-sqlerate.csv) · [Q21 设备计划样本](sel0.8/logs/warm/Q21.SQLerate.1.err#L234)
- **Q3 上轮热态回退本轮未复现。** 四组 warm 均选全 CSD，SQLerate 约 4.26–4.34 s，原生 HOST 约 5.11–5.19 s。 [warm 样本](sel0.1/warm.csv)
- **Q14 冷态和 repeat 首轮。** 冻结版四组冷态均选择全 CSD，慢于 Filter 9.5%–14.6%，三轮累计慢 4.6%–7.1%。固定 CSD− 冷态仍慢于 Filter 4.0%–5.5%，因此填充开销只能解释一部分。全 CSD 在设备侧完成 Hash Join，峰值 workmem 约 60.1 MiB，spill 为零。双开填充时两条路径的专项对照见下方。Warm 已选择混合，比 Filter 快 4.3%–5.6%。 [冷态设备计划](sel0.8/logs/cold/Q14.SQLerate.1.err#L112)
- **Q4 repeat 第 2、3 轮的对照差距与缓存历史一致。** 第 2 轮全 CSD 比 Filter 慢 94.8%–100.6%，第 3 轮切混合后仍慢 40.3%–48.0%。第 2 轮开始前，SQLerate 的 lineitem Heap 文件驻留仅 10.32%–10.86%，主键索引为 68.79%–70.90%。Filter 首轮在 HOST 探测，第 2 轮 Guest NVMe 读取为零。此前固定第 2 轮缓存的 A/B 已确认当时全 CSD 3.269 s，混合 6.189 s。四组 SQLerate 的三轮累计仍快于其各自的固定 CSD+ 与 Filter。Warm 两者执行同类扫描下推路径，最大单轮净差 6.1%，无证据表明误选执行侧。 [缓存日志样本](sel0.1/logs/repeat/Q4.SQLerate.1.err)
- **Q12 repeat 第 2 轮保留全 CSD。** 第 2 轮开始前，SQLerate 的 orders Heap／索引驻留为 41.74%–44.39%／87.66%–90.82%；Filter 首轮实际触碰过所需页，第 2 轮 Guest NVMe 读取为零，二者第 2 轮差距为 16.8%–17.8%。第 3 轮 SQLerate 四组均切混合，与 Filter 的单轮差缩到约 0.6%–1.2%。按已确认的缓存历史差异保留。 [Q12 缓存日志样本](sel0.1/logs/repeat/Q12.SQLerate.1.err)
- **Q1 低选择率冷态略慢，较高选择率因解码切换而变快。** sel0.1 和 sel0.2 的最佳固定全 CSD 比 Filter 慢约 22、47 ms。冻结版从 sel0.5 到 sel0.8，延迟解码从 4 列变成 0 列，Filter 累计 CPU 从 6.426 s 降到 0.499 s，Scan 与 Aggregate.sink 合计增加 4.625 s。设备内部读取均约 6.86 GiB，spill 为零。估价修正见下方专项复测。 [sel0.5 分项](sel0.5/logs/cold/Q1.SQLerate.1.err#L89) · [sel0.8 分项](sel0.8/logs/cold/Q1.SQLerate.1.err#L89)

## Q14 双开缓存冷启动专项

SF8 sel0.1 下强制对比完整 CSD 与双扫描下推接 HOST 并行 Hash Join。两条路径均开启 HPCP 和 DCP，各测三次，净总耗时沿用上述扣除 ExecutorEnd 的口径。

| 路径 | 估价 | 实测执行中位数 | 三轮净总耗时 | 净总耗时中位数 |
| --- | ---: | ---: | --- | ---: |
| 全 CSD | 2.782 s | 3.032 s | 3.284 / 3.078 / 3.075 s | 3.078 s |
| 双扫描下推接 HOST 并行 Hash Join | 3.001 s | 3.110 s | 3.171 / 3.146 / 3.158 s | 3.158 s |

模型预计全 CSD 快 219 ms，实测执行中位数快 78 ms，首轮则是混合路径更快。全 CSD 的 lineitem 扫描加建表估 2.451 s、实测 2.597 s，part 扫描加探测估 258 ms、实测 348 ms。独立跟踪中，HOST 建表的 2.147 CPU 秒有 2.144 CPU 秒处在 lineitem 批次交付窗口内。混合路径的结果读累计暴露于填充 DMA 的等待为每轮 219–276 ms，全 CSD 对应计数为零。DCP 导入计时中位数分别为混合 227 ms、全 CSD 471 ms。这些计时可重叠，不能相加当作填充的净增延迟。

全 CSD 的估价优势偏大，专项中位数支持冷态选择全 CSD。冻结版与不填充的 Filter 对照差距仍保留。此项只做诊断，模型未改，也未复测其他选择率或 repeat。 [混合物理计划](../sf8-sel0.1-q14-forced-cold-20261107/mixed.plan) · [估价分项](../sf8-sel0.1-q14-forced-cold-20261107/cost-breakdown.plan.err) · [重叠跟踪](../sf8-sel0.1-q14-forced-cold-20261107/mixed.overlap-aggregate.trace) · [设备 DMA 汇总](../sf8-sel0.1-q14-forced-cold-20261107/device-cache.log)

## 目标选择率和实际选择率

三个新增 SQL 目录各生成了 22 条正式 SQL。现有校准器在模板允许的参数范围内寻找最接近的值，不同目标可能落在同一参数上。去掉注释后，四组间有变化的 SQL 共 8 条，分别是 Q1、Q3、Q5、Q11、Q16、Q18、Q20 和 Q22。只有 Q1、Q11、Q18 在四组都得到了不同参数。其中 Q11、Q18 变化的是 HAVING 组保留率。

Q4、Q9、Q12、Q14 在四组的 SQL 正文均相同，实际校准范围的保留率分别为 3.84%、5.49%、0.523%、1.295%。因此这些查询在四个目录中的表现应读作相同参数的多次观测。逐表或逐阶段保留率见各正式 SQL 的文件头。
