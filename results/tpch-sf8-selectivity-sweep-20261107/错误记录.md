# SF8 四组目标选择率的错误与待核对记录

## 正确性与资源检查

2,200 次正式执行中，SQL 错误、结果不一致、计时缺失均为 0。12 个阶段各 22 组 FDM 检查均归零。原始运行状态见 [批次状态](batch-status.tsv)，逐次校验列见 [逐次对照](逐次对照.tsv)。

## 已部分修正，保留路径误选

**Q9 已补计 HOST Parallel Hash 执行期扩批，热态误选保留。** 冻结版四组 warm 均选 HOST，sel0.8 repeat 累计落后 CSD+ 5.3%。sel0.1 热态专项确认两处由 8 批扩到 16 批，扩批合计约 164 ms 墙钟。扩展补收建表侧额外读回、重写和重分区估价后，选中的全 HOST 候选从 6.826 s 升至 7.070 s。实际仍选全 HOST，修正后样本比强制 CSD+ 慢 467 ms。实际建表输入约为估计的 1.8 倍，常规建表和探测估价仍低。其他选择率与 repeat 沿用冻结记录。 [专项前后对照](差距记录.md#q9-热启动扩批估价专项)

## 已修正趋势，保留残差

**Q1 冷启动估价已对齐延迟解码切换。** sel0.5 的全 CSD 估价从 5.317 s 改为 6.733 s，最终实测执行中位数为 6.572 s，仍高估 161 ms。sel0.8 的估价从 6.843 s 改为 6.415 s，最终实测执行中位数为 6.055 s，仍高估 360 ms。两组修正前后均选全 CSD。估价和实测排序已一致，剩余偏差接受，冻结版全量记录保留。 [专项前后对照](差距记录.md#q1-冷启动估价专项复测)

## 已完成对照，保留偏差

**Q14 双开缓存时，实测中位数支持冷态全 CSD。** sel0.1 各三轮强制对照中，全 CSD 执行中位数 3.032 s，双扫描下推接 HOST 并行 Hash Join 为 3.110 s。模型预计领先 219 ms，实测领先 78 ms，且首轮混合更快。全 CSD 的扫描建表与探测阶段都估得偏短，混合路径有真实的建表重叠，也有结果回传与填充 DMA 的链路争用。保留优势幅度的估价偏差和冻结版相对 Filter 的差距，未改模型。 [专项对照](差距记录.md#q14-双开缓存冷启动专项)

Q4、Q12 第 2 轮的不同缓存历史已有同条件对照，仍按已解释差距记录。Q7、Q21 的旧误选在冻结版四组测试中未复现。
